# 短视频脚本方案

## 基本信息

- **主题：** BGE-M3 稀疏向量是什么
- **分类：** 技术/AI/工程
- **题目类型：** 概念解释类
- **平台：** 小红书
- **时长：** 60 秒
- **风格：** 通俗类比 + 实操启发
- **目标受众：** 做 RAG、AI 搜索的初级到中级开发者

## 选题简析

- **核心痛点：** 说到向量搜索就只想到稠密向量，不知道稀疏向量有什么用、怎么用，错失更好的召回效果
- **核心信息：** BGE-M3 同时输出稠密向量和稀疏向量；稀疏向量本质是「关键词加权向量」，擅长精确匹配和罕见词召回，和稠密向量互补
- **视频目标：** 让观众理解稀疏向量的核心思想，知道什么时候该用它
- **风险边界：** 不承诺稀疏向量在所有场景下都比稠密向量好；两种向量是互补关系，不是替代关系
- **最小落地方式：** 用 FlagEmbedding 一行代码即可同时获取两种向量，在 Milvus/Qdrant 中做混合检索

## 推荐标题与钩子

- **推荐标题：** 为什么你的 RAG 召回总漏关键信息？试试 BGE-M3 稀疏向量
- **开头 3 秒钩子：** 你的 RAG 搜不到「Transformer」这个词？问题可能出在向量上。

**备选标题：**
1. BGE-M3 的稀疏向量到底是什么？一个故事讲明白
2. 别只用稠密向量做 RAG 了，稀疏向量才是精确匹配的王
3. 稠密向量 + 稀疏向量 = RAG 召回天花板？

## 口播脚本

### 最终口播

你的 RAG 搜不到「Transformer」这个词？问题可能出在向量上。

大部分人做向量检索，只知道稠密向量。把文本变成一串浮点数，语义相近就聚在一起。但它有个硬伤——对罕见词、专有名词、精确匹配非常弱。

这就是稀疏向量出场的地方。你可以把它理解成「聪明版的 TF-IDF」。它知道哪些词对当前文本更重要，然后给这些词更高的权重。搜「Transformer」就真的匹配「Transformer」，不会因为语义相似而跑偏。

BGE-M3 厉害在哪？它能同时输出稠密向量和稀疏向量。稠密向量管语义，稀疏向量管精确匹配。两个一起用，召回率直接上一个台阶。

别纠结二选一。小孩子才做选择，成年人两个都要。

| 部分 | 内容 |

| 解释 | 稀疏向量 = 聪明版 TF-IDF，给关键词加权 |
| 方法/启发 | BGE-M3 同时输出两种向量，互补使用提升召回 |
| 总结 | 两个都要，不纠结二选一 |
