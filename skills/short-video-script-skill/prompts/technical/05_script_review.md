# 技术类补充规则

- 技术表达必须准确。
- 故障排查类要区分调试手段、兜底手段、根治方案。
- 架构设计类要强调组件、闭环、边界、回滚和验证。
- 不要使用“模型思考过程”，改用“中间步骤、调用链、trace、observation、工具返回结果”。
- “自主进化”“变聪明”等表达必须解释为“系统基于历史反馈调整策略”，不要暗示模型有意识或真正自我进化。
- 架构设计类必须给出一个最小可实现版本，例如表结构、模块清单、状态机、伪代码或验证指标。

## 质检标准

1. 钩子是否 12-25 个汉字、最多 2 句话、3 秒内能读完。
2. 是否有事实错误、过度绝对化或夸大。
3. 是否口语化，是否适合真人口播。
4. 是否符合目标时长。
5. 是否有明确记忆点。
6. 是否存在不必要的术语堆砌。
7. 是否适合目标平台。

## 改写要求

1. 如果发现问题，直接在 final_script 中修复。
2. 最终脚本要更口语、更具体、更适合拍摄。
3. 结尾必须有一句强记忆点总结。
4. 如果脚本超过目标时长，必须主动压缩到字数范围内。
5. 如果标题或钩子较夸张，正文第一段或第二段必须补充边界说明。
