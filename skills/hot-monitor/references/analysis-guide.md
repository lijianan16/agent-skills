# 热点判断标准

当前智能体自己判断，不要调用 OpenRouter 或其他外部大模型接口。

对每条结果给出：

- `isReal`：是否是真实信息。广告、标题党、软文、纯转发堆砌、与正文无关的 SEO 页面记为 false。
- `relevance`：0–100，和用户要盯的关键词有多直接相关。同一大领域但没谈这个关键词，低于 40。正文直接讨论该关键词，才可以到 60 以上。
- `keywordMentioned`：标题或摘要里是否出现关键词，或其常见中英文写法、缩写。
- `importance`：`low` / `medium` / `high` / `urgent`。只对关注这个关键词的人有多重要。
- `summary`：一句中文，说明这条和关键词的关系，不要复述标题。

## 丢掉这些

- `isReal` 为 false
- `relevance` 低于 50
- 没提到关键词，且 `relevance` 低于 65
- URL 重复。搜狗跳转链接和落地页如果明显是同一条，留信息更全的那条
- 有 `publishedAt` 且早于 7 天的新闻条目。没有发布时间的搜索摘要可以保留，但报告里标明「时间未知」
- GitHub 不套用上面这条。`github-new` 只丢掉创建早于 30 天的。`github-hot` 只丢掉最近推送早于 14 天的

## 重要程度

- `urgent`：安全漏洞、重大事故、产品停服、刚发布且影响面大的变化
- `high`：明确的新版本、新政策、关键人物的一手消息、数据明显高的讨论
- `medium`：相关教程、评测、普通新闻
- `low`：擦边提及、旧闻转载、来源含糊

来源本身不提高重要程度。微博热搜只说明这个词今天在榜上，不说明事件本身紧急。

## GitHub 仓库

仓库单独写成「新发布的仓库」和「近期仍热的仓库」，不要放进新闻的紧急/重要分级。star 只表示关注度，不表示能用，也不要因为 star 高就标成紧急。

优先留下能直接拿来做 AI 应用的工具：agent、MCP、RAG、推理、编程助手、浏览器或桌面自动化。

这些降到不写，或最多放低优先级：awesome list、学习路线、面试教程、cookbook、纯资源汇总。描述里已经是教程或书单的，不要因为 star 高就留在主列表。
